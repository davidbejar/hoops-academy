# Security review 2026-11 (WP17)

Scope:
- core-service, game-service and athlete-service;
- `libs/common-quarkus` and `libs/contracts`;
- Flutter auth and offline code in `apps/web` (read-only);
- Keycloak realm export, compose nginx, the Helm charts and the CI workflows.

Method: the `.claude/skills/owasp-security` workflow (entry points and trust boundaries, then references, sweep,
triage, report). It uses OWASP Top 10:2025, ASVS 5.0 IDs and the skill's triage rubric: only findings with a
concrete path are reported, and defense-in-depth items are marked as such. Trust boundaries and STRIDE tables are in
[`threat-model.md`](threat-model.md); control evidence is in [`asvs-checklist.md`](asvs-checklist.md).

"Fixed" means changed in this work package (no commits were made; see the WP17 handover for the file list). "Open"
items are tracked in `docs/wp/FOLLOW-UPS.md`.

## Entry points (step 1)
- **Public REST, behind nginx/ingress and the tenant filter:**
  - `/api/core/**`, `/api/game/**` (including `events:batch` ingest and the event feed), `/api/athlete/**`.
  - The `X-Tenant-Id` header, path ids, query filters, JSON and merge-patch bodies.
  - Binary logo upload (`PUT /api/core/tenant/logo`).
- **Platform REST:** `/platform/**` (`super_admin`).
- **Internal REST:** `/internal/**`. Service accounts only (role `service`); blocked at the proxy and ingress.
- **Keycloak:**
  - login, token, end-session and admin console under `/auth`;
  - the Admin REST API, used by core with its service account.
- **Schedulers:** eligibility sweep, usage snapshot, athlete materialisation, onboarding repair (new). These have no
  external input.
- **Browser storage:** localStorage (OIDC tokens, settings), IndexedDB/drift (offline match outbox and cache), and the
  service worker cache.
- **CI and supply chain:** Maven and pub dependencies, base images, GitHub Actions, CDN-loaded CanvasKit.

Authorization is centralised:
- `TenantHeaderFilter` requires membership (else 404);
- `@RequiresTenantRole` on application use cases;
- fine-grained `Authz` and `RosterAuthz` checks;
- RLS on every tenant table.

Role-matrix tests exist per resource. Candidates were traced through these before being reported.

## Detail of the Medium findings

```
[MEDIUM] Match event feed leaks other players' stat events to parents/players (CWE-639, OWASP A01:2025)
Location:   services/game-service — GetMatchEvents.handle; libs/contracts/openapi/game.yaml GET /api/game/matches/{id}/events
Path:       PARENT of player A (member of the tenant, may view the match) -> GET /matches/{id}/events -> all events incl.
            player B's -> client rebuilds B's stat line, which the box score deliberately hides ("View match stats:
            linked / self", docs/domain/authz-matrix.md)
Impact:     Within one tenant only; minors' performance data of other children. No cross-tenant exposure (RLS).
Fix:        Filter the feed for PARENT/PLAYER to team-level events + own/linked players, or document that the full feed
            is intended (live scoring by parents) and align the authz matrix.
Confidence: Confirmed by code reading (game fork review).
```

```
[MEDIUM] Missing audit trail of administrative actions (CWE-778, OWASP A09:2025) — FIXED
Location:   services/core-service (all admin use cases)
Path:       ADMIN changes roles / approves / deactivates; super_admin suspends a tenant -> no durable who/what/when record
Impact:     No accountability or forensic trail for privilege changes (ASVS 16.3.3).
Fix:        core.audit_event (append-only, RLS, platform insert-only) written in the same transaction by every admin use
            case; one hoops.audit log line per event. Tests: MemberResourceTest, GuardianLinkResourceTest,
            PlayerResourceTest, ApprovalRequestResourceTest, TenantResourceTest, TenantLogoResourceTest,
            PlatformTenantResourceTest, AuditEventRlsTest, CoreRlsSchemaMetaTest/CoreRlsIsolationTest.
Confidence: Confirmed.
```

```
[MEDIUM] Shared-device session survives a failed sign-out (CWE-613, OWASP A07:2025)
Location:   apps/web/lib/core/auth/oidc_auth_service.dart:77; oidc_core-4.0.0 user_manager_base.dart:1584-1665
Path:       Sign out while offline -> revocation error swallowed -> end-session navigation fails -> forgetUser() never runs
            -> tokens (incl. offline_access refresh token) stay in localStorage -> next person opens the PWA signed in
            as the previous coach and can record events under that identity.
Impact:     Physical-access attacker on a shared tablet; within the previous user's tenant and permissions.
Fix:        Wipe local session + drift DB first, revoke with forgetUser:false, forgetUser(), then navigate to
            end_session; drop offline_access.
Confidence: Likely (package source confirmed; not reproduced in a browser).
```

```
[MEDIUM] No anti-automation at the edge for token endpoint and events:batch (CWE-307/CWE-770, OWASP A06:2025) — FIXED
Location:   infra/compose/nginx.conf; deploy/helm (ingress)
Path:       Anonymous client -> POST /auth/realms/academy/protocol/openid-connect/token at high rate (password spraying
            across users, which Keycloak's per-user brute-force detection does not catch) / authenticated client floods
            events:batch (500 events per call, projection work per event).
Impact:     Credential attacks across accounts; DoS of game-service and its database.
Fix:        Per-IP limit_req zones returning 429 in nginx; ingress-nginx limit-rpm annotations on dedicated Ingresses.
Confidence: Confirmed (no limits existed); fix verified (see handover).
```

## Checked and fine (no finding)
- **Tenant isolation:** RLS (FORCE) on every tenant table with meta and generic isolation suites in all three
  services, including the new `core.audit_event`. App roles are non-owner and NOBYPASSRLS. Non-members get 404, not 403.
- **Injection:** JPQL with bound parameters only. Native SQL appears only in `*Repository` classes (ArchUnit) and is
  parameterised. The tenant header is strictly parsed as a UUID.
- **`/internal`:** `@RolesAllowed("service")`; `service` is a realm role held only by the three service accounts.
  The tenant is bound from the path or query via `TenantScope` and RLS. The proxy and ingress answer 403.
- **Uploads:** magic-byte detection; SVG and GIF rejected; 512 KB limit; served with nosniff and a restrictive CSP;
  no server-side image decoding.
- **Errors:** Problem+JSON everywhere. A 500 has no detail or stack trace. A 503 never leaks the upstream message.
- **Secrets:** none in the repo (gitleaks). Helm references Secrets only (ADR-0012). core reads every secret from env.
- **Event ingest:** 1–500 events per batch, JSON Schema validation, event ids bound to one match (`EVENT_ID_REUSED`),
  and authz at sync time.
- **Flutter:** PKCE S256 with state/nonce/issuer validation; fixed same-origin redirect; no open redirect; no HTML or JS
  interop sinks; tokens sent only to the configured API base; outbox scoped by tenant and person.
