I want to create an application in java using microservices architecture pattern, the frontend needs to be web but mobile first, progressive loading application kind of thing. The backend microservices will eventually be deployed in kubernetes, we will use podman instead of docker, and for the frontend avoid using node, use something different. For the backend use docker compose but with podman, and then when the app works use kind + Helm + Tilt. You need to write tests for everything. I leave it up to you if this is going to be one big git project or several git projects. For database use a lightweight database that works well in k8s. Make sure secrets are not pushed to git. Look in internet for skills related to clean code, security practices, and test driven development, and add them to the project or projects. The application is going to be a basketball application for basketball acedemies. For the moment there will be no billing module, but that is going to be a possible expansion, so prepare for it. The application will be multitenant, so different basketball acedemies will use it, and they should not be able to see each other contents. Each tenant will have for roles, administrator, coach, parent and player. Playes belong to categories, they cannot be in categories for lower ages but some players may play in higher categories. A coach trains n age categories. An administrator can be also a coach or a parent or both. An academy may have different teams in a particular age group. When a player makes birthday, if he is in a group in which he cannot be he becomes orphan and his coach or and the administrator need to fix this by assigning him to new group. Groups have names or alias, and age category. Also there's gender. A male cannot play in girls and girls cannot play in males groups. However there might be mix groups that allow both genders to play. The coach can have assistant coach, I am not sure if this needs to be a separated role. Coach, assistant  and parent has access to match view. In match view they can enter game data and player stats as the game goes (assists, points, turn overs, etc). A parent can only enter the stats of his associated player (son or daughter) unless it is also an assistant coach or a coach. The assistant coach and coach can enter stats for everybody in the team. Starting team, minutes played, when they came to the court. Coach, assistant coach and parent can enter injuries and expected return date. Coach and assistant coach also have option to enter training calendar, which sets location, schedule, and training plan. For training plan we may be able to enter some predefined plans, but coach can also enter his own. There will be an overall admin role which manages the different tenants, can sign up tenants, and withdraw tenants, can see how many teams and players they have, how many games, and other usage statistics. For an academy, the admin and the coach can add or withdraw players, but if done by the coach it needs to be approved by an admin. The coach can also enter other physical education stats for his playes, like cooper test results with date, etc. For each of these there should be also some indication of the expected level for the age. Each player would have also data about weight and height which can be modified by parents, coach and assistant coach. The players can see their own stats, but also training program given by the coach, and they can mark if they have done it or not, or only partially. Also parents and players can record a planned absence, and the coach and assistance coach can record the player being late or missing a training. Make the plan to be run by different agents, use the model most adequate for each task, some may be for sonnet and some for opus, don't use fable except for the design of the plan.
