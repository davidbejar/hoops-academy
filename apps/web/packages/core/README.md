# hoops_core_api (EXPERIMENTAL)
Tenancy, identity & membership, roster & eligibility, approvals and platform statistics.

Path families (all served by core-service):
- `/api/core/_**` — tenant API; every operation except `/api/core/me` requires `X-Tenant-Id`.
- `/platform/_**` — platform super-admin API (realm role `super_admin`); never exposes tenant content, with one
  documented exception: the identity of a tenant's administrators (`/platform/tenants/{tenantId}/admins`, ADR-0023).
- `/internal/_**` — service-to-service API (client-credentials token with role `service`), blocked at the proxy,
  marked `x-internal` so it is not generated into the Flutter client.

First sign-in (ADR-0024): a login created by a call gets a server-generated temporary password, returned once as
`temporaryPassword` in that call's response (`Cache-Control: no-store`; never stored by the platform). No e-mail
is sent; Keycloak asks for a new password at the first sign-in. A person who already had a login gets no
temporary password and signs in with their own.

Expiry (ADR-0028, core 2.4.0): a temporary password not used within `hoops.temporary-password.ttl` (default 3 days)
expires; the login is disabled in Keycloak until a new temporary password is issued (the re-issue operations).
`Member.temporaryPasswordStatus` and `TenantAdmin.temporaryPasswordStatus` show the state. Core 3.0.0 (ADR-0035)
removes the deprecated alias `POST /platform/tenants/{tenantId}/admins/{personId}/resend-invitation`
(`resendTenantAdminInvitation`): use `issueTenantAdminTemporaryPassword` (`.../temporary-password`, 200).

Audit trail (ADR-0017, ADR-0029, core 2.5.0): `GET /api/core/audit-events` (ADMIN, own academy) and
`GET /platform/audit-events` (super_admin, every academy) read the administrative actions recorded by core. No
retention in v1: rows are kept until a purge job exists (v2). Since core 2.6.0 (decision 16 of 2026-11-06) the
academy list masks the super admin: a PLATFORM actor has a null `subject`, `personId` and `displayName` there.

Authorization follows `docs/domain/authz-matrix.md`; the `Authz:` line of each operation summarises it.
