# Adding a feature to apps/web

## Layout
```
lib/
├── app/            router (go_router), theme, shell scaffold, auth guard, tenant switcher
├── core/           api client setup (Dio + interceptors), auth (oidc), tenancy, error mapping, l10n helpers
├── (packages/<svc> at apps/web/packages — GENERATED by just gen-api, never edit by hand; path deps in pubspec)
├── features/<name>/
│   ├── data/       repositories wrapping generated clients (+ Drift tables for offline features)
│   ├── domain/     plain Dart models/value objects when the API DTO is not enough
│   ├── application/ Riverpod providers / notifiers (state, commands)
│   └── presentation/ screens + widgets (mobile-first, bottom nav, large tap targets)
└── l10n/           app_es.arb (template), app_en.arb, app_id.arb
```

## Rules
- **Contract first**: if the API changes, regenerate clients from `libs/contracts` (`just gen-api`).
- **Every user-visible string** goes through `AppLocalizations` (ARB keys in all three files; Spanish is the
  template, English and Indonesian must have the same keys — the `l10n_keys_test` enforces it).
- **Role-aware UI**: hide actions the role cannot perform (from `AuthzContext` in `/me`), and still handle a
  server 403/404 gracefully.
- **Errors**: map Problem+JSON to `AppError` once (core/errors); screens show localized messages.
- **Offline** (live match only): write to Drift first, sync in background; never block the UI on network.
- **Lists (ADR-0061)**: never read one page and show it as the whole list (the services serve at most 200 a page).
  A list the screen needs whole goes through `fetchAll` (`core/api/fetch_all.dart`) in the repository, which returns
  a `List`; a list that grows without bound pages on screen with the kit's `Pager` (or a "load more"). Prove a whole
  read with a case in `test/core/lists_read_every_page_test.dart` (`ServerPagesAdapter`); mock lists page through
  `MockQuery.page`.
- **Provider lifetime**: a provider whose `build` opens streams, timers or watches is `autoDispose`, so leaving the
  screen ends them (the live match, WEB-01).
- **Shared helpers (ADR-0067)**: dates through `core/time/dates.dart`; field rules, `parseDecimal`, `blankToNull` and
  `formatMeasure` from `core/ui/validators.dart`; a server error code is worded once in `AppError.message` (pass
  `errorText` only for other words in your context); a block inside a page uses `AsyncSection`; a server CSV/PDF uses
  `ServerExportButton`; a mutating notifier reloads with the `Reloading` mixin; a per-id provider family is
  `autoDispose`. Tests: `pumpAsSuperAdmin`, `localizedApp`.
- **Formatting**: `apps/web` uses the default `dart format` (80 columns); run `just web-format` before committing, CI fails on unformatted files.
- **Mobile-first**: design for 360 px width; test goldens at 360×780 and 1024×768.

## Tests per feature (TDD)
Tests run the app's real repositories and generated clients against the demo mock, started empty and seeded per test
(ADR-0070): the `Harness` / `pumpAs` installs a `MockBackend` (`test/support/mock_backend.dart`); seed through the
area's data class (`core_seed.dart`, `athlete_seed.dart`, `game_seed.dart`, `finance_seed.dart`, `audit_seed.dart`,
`platform_seed.dart`) and inject what the mock cannot produce (`fail`, `hang`, `networkDown`, `heal`). Never write a
repository fake; if the mock lacks an operation or a rule, add it to the mock (and its seeding hook), deciding any
difference against `libs/contracts/openapi` with a red test on the mock first. A release build must not hold the
mock (`tool/verify_no_mock.dart`).
1. Provider/notifier tests on the app's `Api*Repository` over a seeded backend.
2. Widget tests for each screen: loading, empty, error, populated, and role variants.
3. Golden test for the main screen (both breakpoints).
4. If offline: Drift repository tests + sync worker tests (`fake_game_server.dart`, the sync worker's contract fake)
   and the projection vectors in `libs/contracts/vectors` (the one copy, read by the tests).
Run `flutter analyze && flutter test` before claiming done.
